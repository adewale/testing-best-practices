# Test quality audit of agentic-mermaid

The multi-input CLI, graph route rollback and logo color checks each have a test that can pass after the behavior it describes breaks. Two also reject a change that preserves the observed output. I verified all three in a disposable checkout. Separately, on the supplied revision, a multi-input render can exit successfully without creating the requested output file.

**Revision and scope.** I audited `adewale/agentic-mermaid` at `f49196e7f5d6d2f0970a4a76fe62644ee5e9d004` with the assigned OpenClaw test-audit guidance. The checkout contained 3,512 tracked files, including 606 `src/__tests__/**/*.test.ts` files. Thirty first-parent commits and 391 reachable commits were present in the shallow history. The audit used the provided Bun 1.4.4 installation and its 614 packages. The read ledger records 27 target files reviewed in full and 25 in part, plus the six assigned guidance documents. File inventory and search hits have their own entries. The ledger notes incidental historical lines returned by a broad target-documentation search. The findings use the current source, relevant target commit history and self-run controls. [Read ledger](read-ledger.json) · [Checkout and installation](evidence/commands/checkout-history-shape.log)

I chose the CLI because it promises to continue after an error, graph bundling because the selected merge changed how routes avoid other ink, and the site/editor tests because their shared brand contract is independently specified. I read the candidate test files in full and followed their owners, callers, overlapping tests, history and CI routes. For large production files I inspected the relevant functions and consumers. ## Test findings

### OC-1 · Repair the multi-input test by putting the bad file in the middle

**Medium.** The test named “renders multiple files, emits a results array, skips bad ones” sends valid A, valid B, then malformed input. It verifies the last error. A command that stops immediately after its first failure returns exactly the expected rows for those inputs. The original feature contract explicitly promises an ordered result for each file, including failures. The package binary reaches `cmdRender` through `runAmCli` and `runPreparedCli`. [Test, lines 85–96](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/__tests__/cli-multi-input.test.ts#L85-L96) · [Owner, lines 274–296](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/cli/index.ts#L274-L296) · [Original feature contract](evidence/commands/original-cli-contract.log)

I replaced the map with a loop that recorded the error and broke. All 14 tests in the owner file passed. Ten selected cases spanning that file, the error-envelope tests and the real CLI E2E file also passed. Those sets overlap. A real binary invocation on good / malformed / good exited zero and dropped the final row. The CLI E2E file already checks both file paths and node IDs for an all-valid pair. The missing-file test also places its error last. [Fault patch](evidence/cli-fault.patch) · [Owner test log](evidence/commands/fault-cli-suite.log) · [Sibling and E2E log](evidence/commands/fault-cli-siblings.log) · [Observed CLI rows](evidence/commands/fault-cli-witness.log)

**Repair the existing case.** Put the malformed input between two differently labeled files. Assert the ordered indices and paths, error code and authored labels. This supplies the expectation directly from the caller. With this scratch repair the owner file passed 14/14 on the baseline, failed the precise case on the early break, and passed 14/14 with the equivalent loop that continued. [Test repair](evidence/cli-repair.patch) · [Failing repair control](evidence/commands/repair-cli-fault.log) · [Passing loop refactor](evidence/commands/repair-cli-permitted.log)

### OC-2 · Compare route coordinates after a rejected bundle

**Medium.** Three assertions across four exercised cases save `edge.points` by reference and later use `toBe`. They cover a blocked marker, two unresolved stroke widths and a protected group header. Their contract is that a rejected proposal leaves the prior geometry intact. The layout pass returns edge membership, and later passes clip and read actual coordinates. Its ownership record itself compares coordinates. The cases originate in PR #449. [Tests, lines 96–133](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/__tests__/layout-bundle-proposals.test.ts#L96-L133) · [Bundling decisions](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/layout/passes/edge-bundling.ts#L275-L296) · [Downstream clipping](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/layout-engine.ts#L1406-L1439) · [Targeted history](evidence/commands/graph-target-blame.log)

A scratch speculative update saved the original arrays, overwrote them in place and restored those aliases after rejection. The four cases stayed green. In the header fixture, both rejected shafts now ran vertically at x = 60 from y = 40 to 70. Their one-pixel strokes extended to x = 60.5 and overlapped the header starting at x = 60.1. **Three sibling State tests caught the broad fault** by checking an emitted SVG shaft against actual node artwork. The whole file consequently failed 3 of 43. The converse control restored original coordinates in fresh arrays. Four pointer assertions failed even though the independent fixture cleared the header and the SVG/layout bytes of two authored public samples matched the baseline. [Geometry witness](evidence/commands/fault-graph-witness.log) · [Owner results by case](evidence/commands/graph-results.log) · [Baseline public samples](evidence/commands/base-graph-public.log) · [Refactored public samples](evidence/commands/permitted-graph-public.log)

**Keep the admission cases and the rendered-State cases.** Deep-snapshot the fixture's point values before calling the bundler and compare the resulting coordinates. Keep the existing membership checks. With this small scratch change, all 43 tests passed on the baseline and on the value-preserving rollback. All four repaired cases joined the three State failures on the damaging rollback. The controls qualify these behaviors and two sample outputs. Performance was unmeasured. ### OC-3 · Assert the effective logo color on the actual elements

**Low.** `cssHex` reads the first matching hex declaration. The public site and editor each consume `--brand-pine` as the logo chip background. The design contract gives `#6FC2A2` and a distinct dark foreground, and keeps the mark independent of the renderer palette. The site build prepends font-face rules to the source CSS. The existing editor browser test covers diagram arrowheads and the editor's inline root theme colors. [Regex and assertions](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/__tests__/chrome-token-lockstep.test.ts#L27-L74) · [Design values](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/DESIGN.md#L4-L11) · [Original brand change](evidence/commands/css-origin.log) · [Coverage search](evidence/commands/shared-brand-siblings.log)

A later `:root` declaration aliased the site's brand color to its action accent. All six tests passed. Chromium computed `rgb(27, 110, 82)` for the actual site mark and `rgb(111, 194, 162)` for the editor mark. In the reverse control, writing `rgb(111 194 162)` for the original color preserved both computed colors and failed two tests with “--brand-pine not found.” [CSS fault](evidence/css-fault.patch) · [Browser observation](evidence/commands/fault-css-browser.log) · [Equivalent CSS](evidence/css-permitted.patch) · [False failures](evidence/commands/permitted-css-suite.log) · [Equivalent computed colors](evidence/commands/permitted-css-browser.log)

**Move the chip comparison to an existing browser boundary.** Assert its specified foreground and background on `.brand .mark` and `.app-mark`. Retain checks for the distinct theme-switch and status-hue contracts. The scratch witness loads both production header fragments and their actual CSS in offline Chromium 156. It checked the fallback chip in the light scheme before shader attachment. The three independent browser runs took 0.90–1.64 seconds each on this host. ## Baseline product observation and policy decision

**OC-4 · Medium.** `am render first.mmd second.mmd --format ascii --output dst --json` exited zero, wrote two successful results to stdout, produced no stderr and left `dst` absent. The equivalent single-input command wrote `dst` and returned its path. The global help describes `--output FILE` as writing the render output there, and the render help says the file always holds the plain artifact. The multi-input branch returns before the destination lookup. The existing file-write proof covers one input. The earlier commit adding the file receipt scoped that work to single-input success. [Baseline reproduction](evidence/commands/multi-output-observation.log) · [Flag and help](evidence/commands/cli-flag-owners.log) · [File-write test](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/src/__tests__/agent-cli-render-formats.test.ts#L76-L90) · [History](evidence/commands/output-contract-history.log)

The mismatch is the successful acceptance of an ignored destination. The desired multi-input file format is an open policy choice. Rejecting that combination with a clear argument diagnostic would preserve current multi-input stdout behavior. Supporting it would require specifying aggregate bytes and the associated receipt. Once chosen, exercise the real destination, exit status and diagnostic in one multi-input case.

## Verification and limits

All test runs used a 120-second outer cap and ran serially within this lane. The unchanged 14-test CLI owner took 0.75 seconds, the 43-test bundling owner 1.38 seconds and the six-test brand owner 0.32 seconds. No timing here estimates CI cost. The ledger gives exact argv, working directories, observed exit codes, seconds and raw logs for discovery, focused validation, controls, history and restoration. It is a lane-authored record. The initial Chromium launch failed because the temporary Unix-socket pathname was too long. A short handle into the same lane's temporary directory resolved setup, after which all three browser states ran. Early search diagnostics for nonexistent documentation paths also remain in the ledger. [Command ledger](command-ledger.json) · [Browser setup diagnostic](evidence/commands/browser-diagnosis.log)

The full unit shards, built-site browser suite, rayner/visual tier, tarball, compiled binary, other platforms, typecheck/lint, live evaluations and broad CI were unrun. The CLI E2E evidence is limited to the selected multi-input cases. The delivered production, test and support diffs are each zero lines. Both checkouts' tracked content was restored and the five scratch-touched files matched the committed bytes in both trees. All proposed changes live in evidence patches.
