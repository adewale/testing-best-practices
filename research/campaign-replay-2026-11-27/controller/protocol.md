# Four-arm replay of testing campaigns and larger-suite audits

This study asks whether the revised testing-best-practices package improves a specific observed decision or executed repair over the current PR #41 package, an unaided subject, and OpenClaw Test Audit. One fresh subject gets each case and arm. Nine historical planning cases and three executed repository audits answer different questions. The stop rule is 48 scheduled subjects, 12 fresh blinded case judges, the specified independent checks and a report of all outcomes. The study has no recurring lane.

## Evidence and scoring

Freeze each task, source manifest, sampling and runtime inputs, hidden criteria, control directions and baseline evidence before launching any subject. Freeze the pre-run correction to the Mermaid visual finding. Section B promises exact regenerated bytes and PNG policy independently promises reproducibility under pinned settings. A second encoding can preserve pixels yet weaken that tested contract. A patch that changes the policy text and drops promised byte evidence has lost a keeper. A justified retention is its own result. The unchanged Mermaid task allows the editor-grader, coverage setup or another verified bounded repair. [Section B testing strategy](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/docs/testing-strategy.md) · [Pinned PNG policy](https://github.com/adewale/agentic-mermaid/blob/f49196e7f5d6d2f0970a4a76fe62644ee5e9d004/docs/quality.md#L316-L359)

For every cell report prespecified findings, genuinely new substantiated findings, refuted claims, unsupported claims and acknowledged open hypotheses. Score the selected repair against its actual contract. A single repair can be valuable if it chooses another target. Evaluate alternative repairs blindly using the same required independent contrast, clean result, allowed-change evidence and relevant keepers. Mark new evaluator controls as exploratory. Under a partial harness, report narrower source evidence and which properties are unresolved. A credible limitation or safe withdrawal of an unsupported checker claim can earn evidence for that decision. A generated candidate file or a warning alone supplies no executed repair evidence.

Pair the original and candidate on the same credible fault and preserved case. Check that the submitted test or checker itself detects an intended user-visible change with a clean passing original behavior after repair. Preserve its selected names, counts, failure diagnostics and runner route, including new, renamed or split candidate tests. A separate evaluator witness establishes that its input is discriminatory. To demonstrate preserved sensitivity, the relevant keeper must reach the intended failure under both selections. Distinguish permitted transformation, retained contract, checker deferral, invalid output, setup exception, empty/filtered collection and unrelated crash. Existing sibling detection limits claims of added suite-wide protection. The case-specific criteria and the common B rubric apply identically to each arm.

Record inventory, accessible files, priority sample, participant-reported files read, native selections and actually executed cases separately. Historical hosted CI, a local evaluator rerun and subject self-report are different sources. Track the task outcome, verification, preservation, false alarms, scope/compliance and available runtime separately. Report paired outcomes by case, including losses, ties, conflicts and unknowns. A tie supplies no observed incremental benefit. The design provides neither a pooled quality score nor a population estimate.

No model regeneration, judge retry, candidate retuning or new campaign follows an outcome. Capture a failed deterministic evaluator invocation and its cause. Save raw reports, diffs, result matrices and hashes before assembling judge packets.
