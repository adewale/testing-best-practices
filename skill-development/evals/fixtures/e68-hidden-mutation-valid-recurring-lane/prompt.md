# E68 — Valid recurring mutation lane keep-probe

A changed-code mutation lane for the authorization predicate killed a seeded auth-bypass sabotage and pinned the repaired fault as a regression. It completed six retained CI baselines in 45–65 seconds under a five-minute timeout. The security team owns it, new actionable survivors create review annotations and page the owner after infrastructure failures, and the policy has no aggregate score floor. It is reviewed quarterly and auto-disables after 90 days without an actionable result. Should we schedule it on protected-branch updates?
